# 주간 업무 보고서 절차

이 문서는 input 폴더 확인부터 backup 저장까지 주간 보고서 작성의 전체 절차를 순서대로 정리한다.

## 역할 정의 (agent team 기준)

기본값은 위임 없이 한 세션이 아래 순서를 그대로 직접 수행하는 것이다. 사용자가 team/에이전트 실행을 명시적으로 요청한 경우에만 아래 역할대로 나눠 맡긴다.

| 단계 | 담당 역할 | 비고 |
|---|---|---|
| 입력 확인 (0~2단계) | `explore` | input 폴더/members.md 대조는 탐색 작업 |
| 수집 (`수집결과.md`) | `executor` | 원문을 표로 옮기는 구현 작업. 원문에 없는 사실은 추가하지 않는다 |
| 분류 (`분류결과.md`) | `executor` | 집계·프로젝트 묶음·반복 이슈 대조 포함 |
| 최종 보고서 작성 (`최종보고서.md`) | `writer` | 문서 순서(6단계)와 문체 규칙을 그대로 따른다 |
| Word/PDF 변환 | `executor` | docx 생성 스크립트 실행, LibreOffice 변환까지 담당 |
| 검수 | 사람(사용자) | AI가 쓴 요약 문단은 사람이 검수해야 실제 보고에 쓴다. 에이전트가 대신할 수 없다 |
| 저장/백업 (7~8단계) | `executor` | output/backup 폴더 생성과 파일 복사 |

팀원(input 파일 제출자)과 사람(검수자)의 역할은 위 표와 별개다. 어떤 실행 방식이든 최종 판단(요약 문구 확정, 표기 통일 승인 등)은 사람이 한다.

## 0. 사전 준비물 확인

아래 세 파일이 프로젝트 루트에 있는지 먼저 확인한다.

- `members.md` — 제출 대상 팀원 명단 (미제출자 판정 기준)
- `작성가이드.md` — 팀원이 지켜야 할 입력 양식
- `이전주_이슈기록.md` (있는 경우) — 반복 이슈 판정 기준

## 1. 입력 규칙 (작성가이드.md)

- 파일 하나에 한 사람의 업무만 적는다. 파일명은 `날짜_이름.txt`
- 상태 태그는 `[완료]`, `[진행중]`, `[이슈]` 세 가지만 인정한다
- 업무는 한 줄에 하나씩 적는다
- 이슈 항목에는 무엇이 막혔는지 한 줄로 함께 적는다
- `[거의 완료]`처럼 세 가지와 정확히 일치하지 않는 태그, 상태 섹션 헤더가 없는 항목은 잘못된 입력으로 간주하고 뒤 단계(분류)에서 미분류로 처리한다

## 2. 입력 확인

1. input 폴더의 모든 파일 목록을 확인한다
2. members.md 명단과 대조해 제출자·미제출자를 먼저 가른다
3. 미제출자는 이름만 별도로 기록해두고(제출 현황 항목), 이후 집계에서 제외한다

## 3. 수집 (`수집결과.md`)

1. 제출된 각 파일을 처음부터 끝까지 읽는다
2. 업무 항목마다 다음을 표로 정리한다: `파일명:줄번호`, 담당자, 상태, 원문, 비고
3. 상태 태그를 확인한다
   - 완료·진행중·이슈와 정확히 일치 → 해당 상태로 표시
   - 일치하지 않거나(`[거의 완료]` 등) 상태 섹션 헤더 자체가 없음 → **미분류**로 표시하고 비고에 사유를 적는다
4. 원문에 없는 내용은 추측해서 채우지 않는다

## 4. 분류 (`분류결과.md`)

1. **상태별 집계**: 완료/진행중/이슈/미분류 건수와 합계를 센다
2. **이슈 상세**: 담당자·막힌 내용·위치를 표로 정리한다
   - 컨펌 주체 등 원문 표현이 서로 다르면 임의로 통일하지 않고 원문 그대로 표시한다
3. **반복/신규 이슈 판정**: `이전주_이슈기록.md`가 있으면 이번 주 이슈와 대조한다. 파일에 이미 결론 문장이 적혀 있어도 그대로 믿지 말고, 담당자·이슈 텍스트를 원본 항목끼리 직접 대조해 재확인한다
4. **팀원별 건수**: 팀원마다 총 건수와 상태 내역을 집계한다 (미제출자는 "미제출"로 표시)
5. **프로젝트별 묶음**:
   - 항목 텍스트에 프로젝트명이 명시된 것만 **확정** 그룹으로 넣는다
   - 텍스트에 없지만 내용상 관련 있어 보이는 항목은 **추정**으로 별도 표시한다
   - 프로젝트명이 전혀 없는 항목은 **기타**로 모은다
6. **표기 유사성 검토**: 프로젝트명 표기가 유사하지만 다른 경우(띄어쓰기 차이 등)가 있으면 목록으로 보여주고 사람 확인 후에만 통일한다. 통일했다면 몇 건을 바꿨는지 문서에 이력으로 남긴다
7. **미분류 항목**: 사유와 함께 별도 목록으로 정리한다

## 5. 최종 보고서 작성 (`최종보고서.md`)

`수집결과.md`와 `분류결과.md`를 바탕으로 문서 순서를 아래로 고정해 작성한다.

1. 이번 주 요약 — "AI 작성 초안, 사람 검수 필요" 표시를 반드시 남긴다
2. 제출 현황
3. 상태별 요약
4. 이슈 상세 (반복/신규 이슈 포함)
5. 팀원별 건수
6. 프로젝트별 묶음 (기타 포함)
7. 미분류 항목

문체는 짧은 문장, 항목당 두 줄 이내, 추측 표현 금지, 완료는 과거형·진행중은 현재형으로 쓴다.

## 6. Word/PDF 변환

1. `최종보고서.md`를 바탕으로 `최종보고서.docx`를 만든다
2. 인쇄 기준 스타일을 적용한다: Arial 계열 서체, 1인치 안팎 여백, 페이지 번호, 헤더에 문서명·기준일
3. 이슈 항목은 빨간 굵은 글자 + 옅은 빨강 배경으로 상태별 요약·이슈 상세·팀원별 건수·프로젝트별 묶음 전체에서 일관되게 강조한다
4. LibreOffice(`soffice --headless --convert-to pdf`)로 `최종보고서.docx`를 `최종보고서.pdf`로 변환한다
5. PDF를 이미지로 렌더링해(`pdftoppm`) 페이지 레이아웃과 빈 페이지 여부를 눈으로 확인한다

## 7. 저장

- `최종보고서.md`, `최종보고서.docx`, `최종보고서.pdf`는 `output/{보고 기준일}/`에 저장한다

## 8. 백업

`backup/{보고 기준일}/` 폴더를 만들고 아래 세 종류를 모두 복사한다.

1. `output/{보고 기준일}/`의 전체 결과물 (`수집결과.md`, `분류결과.md`, `최종보고서.md/.docx/.pdf` 등 중간 파일 포함)
2. input 폴더의 팀원 원본 `.txt` 파일 전체
3. (기존 `분류결과_기존백업.md`처럼 이전에 남아 있던 백업 파일이 있다면 그대로 함께 유지한다)

백업은 원본 그대로 복사이며, 별도 가공이나 요약을 추가하지 않는다.
