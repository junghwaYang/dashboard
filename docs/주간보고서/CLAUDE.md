# 주간 업무 보고서 작업 규칙

input 폴더의 팀원별 업무 파일을 읽어 주간 보고서를 생성하는 폴더입니다.

## 상태값

1. 업무 상태는 완료, 진행중, 이슈 세 가지만 사용한다
2. 상태가 명시되지 않은 항목은 임의로 판단하지 말고 미분류로 표시한다

## 원문 보존

3. 원문에 없는 사실을 추가하지 않는다

## 제출 확인

4. members.md 명단과 대조해 미제출 팀원을 표시한다

## 요약 작성

5. 이번 주 흐름 요약은 AI가 작성하되, 반드시 사람이 검수한 뒤 사용한다

## 분류 절차 (매주 반복)

6. input 폴더의 모든 파일을 읽고, members.md와 대조해 미제출 팀원을 먼저 확인한다
7. 각 업무 항목은 어느 파일 몇 번째 줄인지(`파일명.txt:줄번호`)를 함께 표시한다
8. 상태 태그가 완료·진행중·이슈 세 가지와 정확히 일치하지 않으면(예: "거의 완료") 미분류로 분류하고, 사유를 함께 적는다
9. 이슈 항목은 담당자·막힌 내용·위치를 표로 정리한다
10. `이전주_이슈기록.md`가 있으면 이번 주 이슈와 대조해 반복 이슈 여부를 확인한다. 파일 안에 이미 결론이 적혀 있어도 그대로 믿지 말고 원본 항목끼리 직접 대조해서 재확인한다
11. 상태별 건수, 팀원별 건수, 프로젝트별 건수를 각각 집계한다
12. 프로젝트별로 묶을 때는 항목 텍스트에 프로젝트명이 명시된 것만 확정 그룹으로 넣고, 텍스트에 없지만 내용상 관련 있어 보이는 항목은 "추정"으로 별도 표시한다. 프로젝트명이 전혀 없는 항목은 기타로 모은다
13. 프로젝트명 표기가 유사하지만 다른 경우(띄어쓰기 차이 등)가 있으면 목록으로 보여주고, 사용자 확인 후에만 표기를 통일한다. 통일한 경우 몇 건을 바꿨는지 밝히고 결과 문서에 이력을 남긴다

## 산출물 저장

14. 최종 결과는 `output/{보고 기준일}/분류결과.md`에 주차별로 저장한다
15. 문서 순서는 이번 주 요약 → 제출 현황 → 상태별 요약 → 이슈 상세(반복/신규 이슈 포함) → 팀원별 건수 → 프로젝트별 묶음(기타 포함) → 미분류 항목 순으로 고정한다
16. 요약 문단에는 5번 규칙에 따라 "AI 작성 초안, 사람 검수 필요" 표시를 반드시 남긴다

## 문체 규칙 (작성 단계)

17. 문장은 짧게 쓴다
18. 한 항목은 두 줄 이내로 쓴다
19. 추측 표현("~로 보인다", "~인 듯하다" 등)을 쓰지 않는다
20. 완료된 일은 과거형으로, 진행중인 일은 현재형으로 쓴다

## 전체 절차 및 역할 (2026-08-30)

21. 주간 보고서 작업을 요청받으면 `주간보고서절차.md`에 정리된 절차(입력 확인 → 수집 → 분류 → 최종 보고서 작성 → Word/PDF 변환 → 저장 → 백업)를 순서대로 따른다
22. 각 단계의 담당 역할은 `주간보고서절차.md`의 "역할 정의(agent team 기준)"를 따른다. 기본은 위임 없이 한 세션이 직접 수행하고, 사용자가 team/에이전트 실행을 명시적으로 요청했을 때만 그 역할 배정대로 나눠 맡긴다
23. 절차나 역할 배정을 바꿀 필요가 생기면 이 CLAUDE.md가 아니라 `주간보고서절차.md`를 먼저 수정하고, 바뀐 내용을 이 섹션에도 반영한다
